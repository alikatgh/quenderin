Engineering update · experimental source integration

Adding this week’s open models to Quenderin

18 October 2026 · Quenderin

A busy week of model releases brings several different engineering problems: compact language models, very large mixtures of experts, specialized memory writers, vision and speech systems, and image generators. We have expanded Quenderin’s experimental source integrations and started a separate local image engine. This post records the boundaries of that work; it is not an announcement that every model is available in the store apps.

Nine new text choices

The shared text catalog now has 27 entries. The additions are MiniCPM-V 4.7 1B and 35B-A3B, LFM2.5 24B-A2B, five Jais 3 sizes, and Nemotron 3.5 Bolt 74B-A9B. Each file is pinned to an immutable revision, exact size and SHA-256 checksum across desktop, Android, iPhone and Mac.

These are manual experimental text options. MiniCPM’s image and video inputs are not connected by this update. A model’s small active parameter count does not mean its full weights fit in the same amount of memory: the MiniCPM 35B file is about 21.17 GB, Liquid’s is 14.53 GB, and the mixed-quantization Bolt file is 22.02 GB before context, caches and working buffers.

Architecture and conversation handling

Jais 3 needs the K2 Horizon architecture, its Arabic-aware tokenizer and its own conversation format. The new adapter follows the publisher’s low-reasoning prompt and filters the private reasoning stream before showing the final answer. An incomplete reasoning segment is never flushed into the conversation. Unsupported tool and grammar requests are refused.

Bolt needs more than a familiar model-family name. Its hybrid architecture has layer-specific expert counts, widths and top-k values; its GGUF stores top-k as an array. The runtime backport handles those differences and adds tiny generated-tensor fixtures. A compiled capability check keeps an older engine from attempting to load these files. Automatic recommendations continue to exclude the experimental integrations.

A separate engine for local images

stable-diffusion.cpp provides the source route for FLUX 3 Image Klein and MOSS Image Base/SFT. Quenderin now has a pinned, isolated image runtime, image workspaces in the native Apple, Android and Electron desktop source, and desktop command-line generation. Its patched GGML implementation stays in a separate dynamic library so it cannot replace or collide with the text engine’s GGML symbols.

The component manifests cover the diffusion model, text encoder, VAE and, for MOSS, tokenizer. Public MOSS components can be installed explicitly; retained parts are reused only after checksum verification. FLUX’s publisher-gated files require the user’s own access and license review, followed by local import. Quenderin does not accept those terms on the user’s behalf.

Generation uses local components and writes one new PNG. Existing files are preserved. Dimensions, steps and threads have explicit limits; desktop process output and job duration are bounded, and cancellation reaches the native engine. The initial native hardware gate requires 24 GiB of available memory, so ordinary phones will show an explanation instead of offering an unrealistic generation button. This threshold is conservative, not a measured peak-memory result.

The desktop source commands are quenderin image models, quenderin image verify and quenderin image generate. They verify complete components and the pinned executable before launching it. FLUX takes a full scene caption; this integration does not automatically expand a short prompt with another model. Reference-image generation is available at the C interface and is not yet exposed by every app workspace.

The desktop Images screen uses native folder and save dialogs, checks the prepared components, and previews the validated PNG from disk. It keeps captions after errors and when switching workspaces. A browser dashboard can inspect the presets but needs the desktop app for local file selection and generation. This interface has been exercised with explicitly labelled UI fixtures, without loading model weights.

What has actually been checked

Host fixtures cover catalog parity, source provenance and recovery, publisher prompt formatting, split reasoning markers, component tampering, output preservation, cancellation and packaging failure conditions. The native image runtime and new text graphs also have hosted compilation checks. The linked source review records their current results.

No model weights were downloaded onto the development Mac, and no simulator or physical device was run for this work. Full-weight inference, generated-image quality, peak memory, speed, rendered native UI and new store availability remain unverified. The native Apple and Android source integrations and desktop commands should be evaluated against those limits.
