Native connections and remote-agent delivery checklist

Quenderin will provide three explicit execution destinations in its native SwiftUI and Kotlin/Compose apps: on-device models, DeepSeek's API, and a remote DeepSeek Harness on the user's computer. Every conversation identifies its destination, model, workspace and tool execution location. Changing a destination never silently transmits an existing local conversation or attached documents.

5. Secret protection and enforceable bounds

  • Keep model keys out of source, bundles, logs, transcripts, screenshots, diagnostics, exported sessions and unencrypted backup.
  • Restrict direct credential transmission to the approved TLS origin and reject redirects/cross-origin credential forwarding.
  • Keep remote model keys on the Host and relay payloads encrypted end to end.
  • Document visible routing/account/presence metadata and authentication-server credentials separately from encrypted business payloads.
  • Redact diagnostics and reports before transmission; allow user-selected content only and exclude secret-bearing payloads.
  • Revoke active device access and prevent reconnect after revocation.
  • Set bounded runs/session, Host concurrency, tool calls, deadlines, message sizes, file transfers, queues, retries and connection lifetimes.
  • Fail closed on missing budgets/configuration and test the independent stop.
  • Use user-owned provider accounts initially. Verify approved allowance and provider-enforced spending ceilings before activating funded infrastructure.

DSH Remote crypto preparation

This isolated Rust facade implements the fixed DSH Remote v1 suite Noise_IK_25519_ChaChaPoly_SHA256 using maintained Snow primitives. It has no network, persistence, relay, enrollment, provider, or native app activation. Its complete lockfile is reviewed and the locked host checks pass at source e7baa288e898c823e0b83cab465682b25b67b27c in run 39904655943.

Nine Rust tests, clippy and both actual generated-binding runtime probes pass. Native app linking and platform validation remain separate release gates.

The synchronous UniFFI surface is deliberately narrow:

  • NoiseIkSession.create(role, localPrivateKey, enrolledRemotePublicKey, connectionId, hostDeviceId, clientDeviceId).
  • derivePublicKey(localPrivateKey) returns only the corresponding public key for enrollment, using the maintained Snow DH provider. Private input generation and secure persistence belong to the native platform CSPRNG/vault.
  • initiate() emits an empty initiator message 1 exactly once.
  • readHandshake(message) authenticates the enrolled static key and rejects nonempty payloads before a response or transport state is created. Responders emit empty message 2 in response. It returns complete = true only after successful finalization. No application plaintext crosses the handshake API.
  • encrypt, decrypt, counters, and idempotent shutdown.

shutdown closes protocol state while retaining a usable language wrapper that returns a typed Closed error. Kotlin's generated AutoCloseable.close()/use releases its object handle separately; Swift releases the wrapper through ARC. Do not export a Rust method named close: it collides with UniFFI's generated Kotlin lifecycle method. Call shutdown when ending a session and then release the wrapper using its language's normal ownership rules.

There is no public nonce setter, private-key generator/export, split-key access, deterministic entropy, caller-provided suite, or async task/callback. Generated Swift/Kotlin source is obtained from the same locked host library metadata, not handwritten to imitate generated bindings.

Swift needs its generated C header and module map; Kotlin needs the matching native library and JNA integration. No such binaries or app linking are supplied by this milestone.

The exact UTF-8 prologue is DSH-REMOTE\0v=1\0connection=…\0host=…\0client=…. Empty/NUL-containing fields and fields over 1,024 UTF-8 bytes are rejected. Noise messages are limited to 65,535 bytes, including handshake overhead/AEAD tags. A mutex covers each complete state/cipher/counter operation.

Authentication/identity failures during handshake close the session. Transport tag failures, including replay, return no plaintext and do not advance counters; the next valid in-order frame remains readable. This matches the pinned upstream wrapper's rejection/continuation behavior. An exhausted counter closes the session before encryption/decryption.

All facade-owned private input and temporary plaintext buffers use zeroize. Debug/error output contains no key, identity or payload values. Snow's default X25519 provider is wrapped only to reject an all-zero shared result; no primitive is implemented here.

Snow 0.10 does not promise erasure of all its internal DH/cipher/handshake copies, nor can UniFFI erase foreign-language caller copies. Closing drops Snow state and clears facade-owned buffers; complete process-memory erasure is not claimed. Callers must protect input lifetimes and shut down abandoned sessions. A poisoned state lock fails closed.
