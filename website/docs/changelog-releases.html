Changelog

App Store dates use UTC. Dated engineering entries record the source and verification scope at the time. See release status for storefront availability.

Unreleased

PR #250 merged to main on 27 November 2026 at 11:03 in Ulaanbaatar (6f16e273). Its changes remain unreleased.

Added
  • Local API for macOS. The opt-in API adds Ollama-style local access via OpenAI-compatible chat completions and an installed-model list. It binds to loopback only and is off by default. See the local API guide.
  • Thinking modes. Choose Off, Auto, or Hide in chat settings.
  • quenderin run <model> [prompt]. Start an interactive chat or print a single reply. The command can download the selected model if needed.
Changed
  • Vision in the Apple chat composer. The still-image path is wired behind the disabled FeatureFlags.visionInChat flag. Android defines the same flag and documents the future routing. See the vision implementation note.

Apple 0.6.3 — iPhone App Store (2026-11-24)

Released at 2026-11-24T22:00:09Z (25 November in Ulaanbaatar). The current Mac App Store version is 0.6.1.

Added
  • Experimental Kromoss local image generation with an optional 8-step mode.
  • Experimental on-device speech recognition.
Changed
  • Refreshed the on-device engines and model catalogs. Experimental entries require manual selection. Model downloads begin only when you choose a model.

Full-weight inference for the new experimental entries remains unverified.

Engineering — Kromoss and Hex source integrations (2026-11-22)

See the engineering post for platform coverage and host fixture results.

  • Kromoss (lodestones/Kromoss, Apache-2.0). The symbol-isolated diffusion C ABI (native/diffusion) moved to v2 with QUENDERIN_DIFFUSION_KROMOSS = 4 and QUENDERIN_DIFFUSION_KROMOSS_DMD2 = 5, explicit cfg, flow_shift and lora_path, and an upstream QKV LoRA key-remapping patch for the 8-step DMD2 LoRA, reusing MOSS Image text encoder/VAE/tokenizer artifacts. Wired through the C CLI/JNI, desktop TypeScript, Apple Swift and Android Kotlin.
  • Speech (anomalyco/hex + anomalyco/transcribe.cpp, MIT). Silero VAD v6.2 and 20 speech presets are pinned in shared/speech-model-catalog.json, behind the native/speech C ABI, a JNI bridge, desktop quenderin voice commands, and Apple and Android speech engines.
  • Verification scope. Native harnesses and unit suites ran against synthetic weights and audio fixtures (inferenceVerified: false). No multi-GB weights were downloaded and no phone or simulator inference was run.

Apple 0.6.1 — iPhone and Mac App Store (2026-11-09)

Released at 2026-11-09T22:18:47Z on iPhone and 2026-11-09T23:16:40Z on Mac. See the iPhone version history and the Mac version history.

Added

Engineering — mobile MAX bindings (2026-10-26)

  • Refresh the missing mobile MAX inputs: main 8d5597… still has no Android/Adreno/Qualcomm/Dragonfly source, the only official release is max/v26.7.0, 26.7.0 publishes no Android/iOS wheel, no MEF exists, and the demo author has no public build source. The MLX tokenizer is recorded as an unadopted, unverified candidate. MAX stays blocked and unselectable.
  • Add an Android JNI bridge and pure-Kotlin facade over the canonical C boundary: registry IDs, run-scoped callbacks/cancellation, supplementary Unicode and embedded NUL, explicit close-while-busy, and a hosted JNI/JVM fixture with a test-only synthetic runner. Production links no runner.
  • Add an Apple SwiftPM C target staged byte-for-byte from the canonical C boundary with a SHA-256 receipt, plus a Swift wrapper for receipts, capability, streaming, cancel and close. Close waits for the active run; tests use a test-only Swift runner. Production links no runner.
  • Harden the boundary: Android validates exactly 64 lowercase hash bytes before copying and snapshots the caller's file list; Apple cancel holds the model pointer lock across the bounded native call so close cannot free it mid-cancel. Both bindings add run-specific pending cancellation so a cancel before native admission is honored and a delayed token cannot cancel a later run.
  • No vendor SDK, runner, weights, simulator or device was used. Neither binding is wired into model selection; phone performance/UI and store submission remain deferred.

Engineering — mobile MAX adapter boundary (2026-10-25)

  • Add a vendor-neutral model-adapter boundary for a future mobile MAX backend: exact file sizes and SHA-256 receipts, exact runner ABI, telemetry/crash opt-outs, single-flight leases, bounded prompt/output/context/stream budgets, UTF-8 reassembly, token-boundary cancellation, capability probing and numeric-only performance reports. It loads no vendor runtime and contains no tokenizer, sampler, weights or GGUF loader.
  • Add an inert runner double and sanitizer fixture covering verification failures, symlinks, opt-outs, streaming, split UTF-8, cancellation, sink abort, runner failure, output caps, context clamping, invalid requests and cleanup. Host compilation only; no SDK, weights or device.
  • Record the mobile MAX audit in native/max-runtime/mobile-lock.json: pinned MAX 26.7 source contains no Android/Adreno/Qualcomm/Dragonfly paths, the Bonsai 2B GGUF is pinned but has no reviewed MEF/tokenizer/cache contract, mobile redistribution and telemetry are unreviewed, and the reported Snapdragon demonstration has no located public source/build recipe.
  • Keep mobile MAX out of Automatic and reject unverified support, inference, phone-performance and store claims in a checked lock. Phone validation and store submission remain deferred; no model-weight download, simulator or physical-device run was performed.

Engineering — October open-model integrations (2026-10-18)

  • Add nine pinned experimental text entries across all catalogs: MiniCPM-V 4.7 1B/35B-A3B, LFM2.5-24B-A2B, all five Jais 3 sizes and Nemotron 3.5 Bolt 74B-A9B. Use complete model sizes, conservative memory floors, manual selection and compiled runtime gates. MiniCPM vision/video remains unavailable.
  • Backport K2 Horizon, Arabic tokenization and per-layer Nemotron expert metadata onto the pinned Prism/Muse engine. Add publisher-specific Jais/Nemotron prompts, bounded final-answer filtering and generated-tensor graph/save-reload fixtures.
  • Preserve patch preimages and recover from partial filesystem failures without replacing concurrent changes; failed recovery retains original backups.
  • Add a separately built, symbol-isolated stable-diffusion.cpp C ABI for FLUX 3 Image Klein and MOSS Image Base/SFT. Pin every component and the patched GGML source. Add native and Electron image workspaces and desktop image models/verify/generate commands, explicit installation/import, hashing, progress, cancellation and export.
  • Keep FLUX publisher access/license review with the user. MOSS installation is explicit. The native image gate requires 24 GiB available memory; this is not a measured inference-memory claim. Existing outputs and corrupt originals are preserved. Bound native requests, output, subprocess duration and concurrency.
  • Add native/desktop package identity checks, private runtime exports, Android dependency-closure/16 KiB checks and signed Apple image-framework verification.
  • Record remaining gaps for Super VL, Step 5, Beam, Granite Switch, Hy-Memory and the announced E4B artifact. Do not list these as ready chat downloads.
  • No local model-weight downloads or simulator/device runs. Full inference, native rendered UI, performance and new store distribution remain unverified.

Engineering — Bonsai 2 and Muse Spark Open (2026-10-16)

  • Added experimental Bonsai 2 2B, 4B, and 9B manual choices across Android, iOS/macOS, and the shared desktop catalog. PTQ1_0 downloads are pinned to immutable publisher revisions, exact sizes, and SHA-256 checksums.
  • Use size-specific conservative memory estimates for the verified small Bonsai files; preserve runtime checks, headroom, the 4,096-token cap, and existing defaults.
  • Include PrismML in latest-release discovery and bundled offline metadata. The native release list checks runtime compatibility as well as memory fit.
  • Add experimental native Muse Spark Open text-chat integration: a verified text architecture backport onto the pinned Prism runtime and a compiled capability probe. Older runtimes cannot enable it from catalog metadata alone.
  • Treat its 22 Q2_K GGUF shards as one pinned 304.08 GB installation, with exact per-file sizes/checksums, complete-set validation, bounded sequential transfers, cancellation and verified-part reuse. Isolated or renamed split imports fail closed.
  • Add the Muse prompt adapter and bounded final-channel streaming parser. Private reasoning stays hidden; unsupported raw, tool and grammar requests are rejected. Require conservative memory headroom and cap context at 4,096 tokens; ordinary phones cannot fit this model. No distributed or remote execution is introduced.
  • Keep Muse out of automatic recommendations. Electron/CLI Muse installation stays unavailable until its multipart and chat adapters are implemented.
  • Add an engineering post explaining the implementation, verification boundaries, and improvements: graph correctness, measured memory/performance, recovery, structured tools, multimodal inputs and upstream maintenance.
  • No model weights were downloaded onto the development computer and no simulator or device was launched. Signed builds, full Muse inference and store publication were pending at this milestone.

Paged MoE — frontier-class agent quality on 16 GB machines
  • New catalog flagship: Qwen3.6 35B MoE (qwen36-35b-a3b, UD-IQ3_XXS, 13.2 GB, sha256-pinned, all platforms + shared manifest). Only ~3B of 35B params run per token, so with mmap the OS page cache streams the experts from disk — measured 17.3 tok/s on a 16 GB M4 (CPU-only, 4–6 GB resident, zero swap). Directly attacks the "agent quality is model-bound" ceiling.
  • MoEShape (Swift): detects the …-35B-A3B naming convention and estimates the paged RESIDENT set — open-catalog search & fitness no longer tell a 16 GB Mac that a runnable 13 GB MoE "needs 20 GB". Filters gate MoE by ACTIVE params (size class per token) while download caps stay honest on total size.
  • GPU offload is now a policy, not a constant: Swift GpuOffloadPolicy (twin of Android's GpuOffloadPlanner) keeps Metal offload when weights fit the app budget and goes CPU-only
    • mmap when they don't (wiring an over-budget file thrashes the Metal working set); desktop

gpuOffloadFits does the same before trying GPU.

  • Agent-screen upgrade copy is MoE-honest (13 GB download, SSD-streamed) — never the generic "slightly slower replies". check_catalog_parity.py fixed to parse hyphenated quant ids.
Russian-first: UI localization + honest model-language info

Known gap: long Settings captions built from concatenated literals are verbatim strings (SwiftUI skips localization) — needs a source-side pass.
  • Every catalog model states its languages (languages field, all platforms + manifest, decode-safe for older persisted entries) — shown in the model profile, localized. Honest about Russian: the Llama 3.2 tier says "no Russian" out loud (a 1B answered a Russian user in English — the info was missing where the choice is made).
  • Chat prompt mirrors the user's language on all three platforms ("Always reply in the same language the user writes in") — small models default to English otherwise.
Autopilot — run a goal without babysitting it (macOS)
  • "Allow all steps for this goal" on the per-step approval dialog: one grant covers the rest of the run; the broker resets at the next goal, so it never leaks.
  • Settings → Agent → Autopilot: goals start pre-approved from step 1 (for runs you can't sit in front of). What it never skips: the SafetyBlocklist (refuses before approval is even consulted), standing consent tiers, the audit ledger, and undo. Off by default.
  • New scripts/build_mac_dmg.sh — local-test DMG in one command (build → sign consistently → package); fixes the hardened-runtime/adhoc Team-ID launch crash.
