Security Policy

Reporting a Vulnerability

Report suspected vulnerabilities through GitHub private vulnerability reporting. Keep vulnerability details out of public issues and pull requests. Do not include real credentials or personal data; use sanitized examples.

Please include the following information:

  • Description of the vulnerability
  • Affected platform and exact app version or source commit
  • Steps to reproduce the issue
  • Potential impact
  • Suggested fix (if any)

We assess reports privately and coordinate fixes and disclosure with the reporter. Response and release timing depend on the impact and the verification required.

Security Model

Desktop local-model inference uses local GGUF files executed via node-llama-cpp; this inference path does not require a cloud LLM provider key. The local dashboard uses a separate, per-launch authentication token. Configuration is via environment variables and the in-app Settings UI.

Local server binding

The dashboard/agent server binds to loopback (127.0.0.1) by default on port 3000 (override with --port). Mutating API requests, protected user-data reads and WebSocket connections require the per-launch token. Public readiness and catalog routes remain accessible without it. Keep the server on loopback; the token does not make a network-exposed server safe.

Defense-in-depth on the local server:

  • CORS and WebSocket connections are restricted to localhost origins (a literal null origin is rejected); the WebSocket upgrade is pinned to /ws.
  • A Content-Security-Policy header is set.
  • JSON request bodies are capped at 256 KB; attachment count/size are capped.
  • /api/docs serves only an allowlist of public docs.
  • Device-sourced UI XML is parsed with entity expansion disabled.

There is no rate limiting. Loopback binding, token authentication and origin checks are separate controls; they do not replace supervision or protect against every process running under the same user account.

Autonomous device control — experimental

The agent issues real input to the host and any connected device. Action safety is gated by an experimental, English keyword blocklist that is not a robust safety boundary — it misses paraphrases, other languages, and prompt-injected instructions from on-screen content. Treat the agent as experimental, supervise it, and do not point it at sensitive apps or accounts.

What stays local
  • No telemetry or tracking; the agent's data lives under your home directory.
  • Open source and auditable.
  • After the one-time model download, normal operation needs no network.

Security Updates

Security fixes are documented in the changelog and applicable GitHub releases or security advisories. A merged source fix does not establish that updated native apps have been published to their stores.

Dependencies

  • CI runs npm audit --audit-level=high for the root npm dependency tree.
  • .github/dependabot.yml configures weekly version updates for the root and UI npm packages, GitHub Actions and Android Gradle dependencies, with separate security-update groups. Automatic security-update PR generation is controlled separately by repository settings.
  • GitHub Dependabot alerts, secret scanning and push protection are enabled. Their coverage depends on recognized dependencies and supported secret patterns; they do not establish that the project is free of vulnerabilities or secrets.
  • The Secret scan workflow checks tracked files with the project's bounded scanner.
  • Review dependencies before updating.

Responsible Disclosure

We follow responsible disclosure practices:

  • Security researchers are credited in release notes (if desired)
  • We aim to fix vulnerabilities before public disclosure
  • Disclosure timing is coordinated with the reporter

Thank you for helping keep Quenderin and its users safe!

Quenderin — Privacy Policy

Last updated: 2026-10-28 Contact: quenderin@aulenor.com

Public policy: https://quenderin.org/privacy. Keep this source and the hosted policy consistent.

The short version

Quenderin's local chat, image, and memory features process content on your device. Optional DeepSeek, My computer / Remote Harness, and Step 5 CUDA-host features send data to the provider, server, or computer you choose, as described below. Their conversations are separate from local chats; local chats, attachments, and memory are not automatically uploaded to them.

Quenderin does not provision a hosted AI service. Model discovery, downloads, and the website also make network requests.

1. Who we are (Data Controller)

The controller responsible for personal data described here is The Quenderin Project. Address: available on request. Contact and data protection contact: quenderin@aulenor.com.

2. The app: local features and optional connections

Optional features described here apply only to app versions that include them.

  • Local chat. Installed local models process prompts and conversations on your device. After the required model files are installed, local inference can run offline.
  • Images and attachments. Local image generation and image or attachment processing happen on your device. The optional direct DeepSeek and Step 5 conversations accept text, not local image or file attachments.
  • Hy-Memory. This local feature proposes facts from the conversation you choose to review. Proposals start unselected; only those you select and approve are saved in the app's private local memory storage. Nothing is saved automatically.
  • Accounts. Local features require no Quenderin account. Direct DeepSeek uses your existing DeepSeek API account. Remote Harness signs into an existing account on the server you configure; it does not create that account. Quenderin does not provide automatic cloud sync.
  • App diagnostics. Quenderin does not send app usage analytics, telemetry, or crash reports to the Quenderin Project.

User-enabled operating-system or device backups may include local app data on Apple devices; these are separate from Quenderin, which does not provide automatic cloud sync.

Optional direct DeepSeek connection

When you choose to validate and save a DeepSeek connection, the app sends your API key over HTTPS directly to api.deepseek.com/models to check available models. This check does not send a conversation or make a paid inference request. The saved key is protected in Apple's device-only, non-synchronizing Keychain, or encrypted using Android Keystore on Android. Protecting the saved key does not prevent DeepSeek from receiving it for authentication.

After you approve using a separate DeepSeek conversation and choose Send, the app sends your new text and that conversation's completed earlier messages, including returned reasoning when present, directly to api.deepseek.com/chat/completions. The request also contains the selected model, thinking settings, and output limits, and authenticates with your API key.

The direct connection does not enable tools or attach local chats, files, images, or memory. DeepSeek receives ordinary connection information such as your IP address and can associate requests with your API account. Inference uses that account and may incur provider charges.

The app saves this separate conversation locally, including answers, reasoning, incomplete turns, model settings, usage counts, and connection references. Removing the connection or saved API keys keeps the saved conversations. The current DeepSeek screens do not offer per-conversation deletion. There is no automatic expiry of saved DeepSeek history.

DeepSeek controls its handling of requests under the terms applicable to your account, including its Open Platform terms. Quenderin does not set DeepSeek's retention period or promise that API data is never retained or used for other purposes. Removing a key or local data does not delete provider records or close your DeepSeek account; use the provider's account and privacy-request channels for those requests. You can stop further direct sends by removing the connection or choosing not to send.

Optional My computer / Remote Harness connection

You enter the HTTPS origin of your Remote Harness server and choose Authorize this device. Sign-in sends the account email and password you enter to that server. Device enrollment sends a generated device identifier, device name, platform, public identity key, and client version.

The password is used for sign-in rather than saved as a credential. The app stores a private device identity and rotating access and refresh tokens in a separate Apple Keychain record or Android Keystore-encrypted storage. Tokens are sent to the configured server to authenticate connections and renew authorization.

You choose a computer and verify its full identity fingerprint; the computer must also authorize this device. Session payloads are encrypted between the app and that computer using the Noise protocol. The server still handles account and device records, connection and routing identifiers, public keys, and ordinary network information such as IP addresses, connection times, and traffic sizes.

This session encryption does not hide sign-in or enrollment data from the server, or hide decrypted session content from the selected computer.

Choosing Send sends the task text, session and command identifiers, and client time-zone context to the selected computer. Other actions send their corresponding session commands, model selections, or one-time tool approval decisions. The app can receive workspace paths, session history, answers, reasoning, tool events and approval details, and bot information from that computer.

Tasks and tools run on the computer; its configured AI providers, tools, and services may receive data according to the task and its configuration. The app does not automatically import local chats or its direct DeepSeek API key into this connection.

The app saves connection details, trusted fingerprints, selected sessions, drafts, received history, and command recovery records separately on this device. These records have no automatic expiry. An authorized connection may reconnect and refresh remote history when the app returns to the foreground.

Disconnect stops the connection and automatic recovery; it keeps saved credentials, drafts, and history. It does not delete the server account, revoke the device's server authorization, stop an already-running task, or delete computer/provider records.

The server administrator and computer operator control their own records and deletion; contact them and any downstream provider about retained copies.

Optional Step 5 CUDA host

You configure the gateway origin for your own CUDA host. Checking its backend contacts that host without sending conversation content. If you enable the consent control and choose Send to CUDA host, the request contains your current prompt and the preceding messages in that separate Step 5 conversation.

Local chat history is not automatically copied into it. The configured origin and Step 5 conversation are held in app memory rather than saved as local chat history.

The host receives that text and ordinary connection information, such as your IP address. Its operator controls how it processes, logs, retains, or deletes received data under its own policies and configuration. Quenderin does not control that host. You can disable consent to prevent further sends; changing the host resets consent. Clearing the conversation in the app does not delete copies the host may already hold.

Model discovery and downloads

These features use network requests independently of local inference:

  • Model downloads. When you choose to download a model, the app fetches the model file you selected directly from Hugging Face (huggingface.co), a public model host. This is an ordinary download of a public file. Hugging Face receives the requested file and ordinary connection information, including your IP address, and may log the request under Hugging Face's privacy policy.
  • Model-catalog search (optional). If you search for a model to download, the search term you type is sent to Hugging Face's public model index to find matching files. Nothing else is attached to that request — no conversation content, no account, and no identifiers beyond what any web request carries. Search terms are used only to return catalog results and are never stored by us.
  • Latest release metadata. In app versions with the latest-releases view, opening model selection checks a small public catalog at quenderin.org/api/model-releases. No conversations, files, account, device profile or search terms are sent. Our hosting provider processes ordinary request information, such as IP addresses, for routing and security. Results are saved on your device for offline browsing; the request never downloads weights or changes your active model.
Data stored on your device
  • Conversations and app settings are stored locally in the app's private container.
  • Downloaded models are stored locally and can be several gigabytes.
  • Approved Hy-Memory proposals are saved separately in private local memory storage.
  • Saved DeepSeek and Remote Harness records are separate from local chats. Their history directories are excluded from app-managed backups; saved credentials use the protections described above. This does not erase data already sent to a remote destination.
  • Step 5's separate conversation is held in app memory. Deleting local data does not delete content already received by the host you chose.
AI-generated content

Responses are produced by a model running locally, by DeepSeek, or by your chosen computer or Step 5 host. Output may be inaccurate, offensive, or otherwise objectionable. Do not rely on it for professional, legal, medical, or financial advice.

In Android app versions with a Report control, you can select a response, edit the excerpt, choose a reason, and add an optional note. Only when you choose Send report does the app send that excerpt, reason, note, source feature, a random report identifier, platform, and app version to the Quenderin developer's Google Apps Script inbox for manual review.

The inbox adds a receipt identifier and received time. Reporting requires no Quenderin or Google account. The app adds no account or device identifier to the report.

The app does not automatically attach your whole conversation, attachments, memory, API keys, or diagnostics to a report. Review the text before sending, because it may contain personal information you choose to include. Google hosts the report storage and processes ordinary connection information, such as your IP address and request time, under Google's privacy policy. Processing may occur outside your country; this feature does not guarantee a particular storage location.

The developer keeps submitted reports for review, without automatic expiry. Clearing a chat or removing local app data does not delete a report already sent. For access, correction, or deletion requests, contact quenderin@aulenor.com; include the report receipt if available so we can identify the report.

If you choose to email support or report a response through an email action, your email application prepares the message for you to review and send. The support address receives the content you send and the email's ordinary sender and delivery information. Opening that action is separate from sending a report.

3. This website

The website stores an appearance preference in your browser's local storage. It has no sign-up form. Our hosting provider, Cloudflare, processes ordinary request information such as IP address, time, and page requested for delivery, security, and operation under its privacy policy.

The site's current Content Security Policy blocks third-party analytics scripts and outbound analytics connections. We do not use this site to build advertising profiles.

4. Following the project

This site collects no newsletter email addresses. You can follow the project on GitHub. GitHub processes activity there under its own privacy statement; public activity, such as starring the repository, may be visible to others.

5. Your rights

Under the GDPR/UK GDPR you have the right to access your data, rectify it, erase it, restrict or object to processing, data portability, and to withdraw consent at any time. You also have the right to lodge a complaint with your local data protection supervisory authority.

Under the CCPA/CPRA, California residents have the right to know, delete, correct, and opt out of sale/sharing of personal information. We do not sell personal information. Optional transfers to the recipients described above occur when you use those features.

To exercise any right, contact quenderin@aulenor.com. You control data stored locally on your device through the available app and operating-system controls; contact us for help with saved data that has no in-app deletion control. Removing a connection or clearing local data does not erase records held by DeepSeek, a Remote Harness server or computer, a Step 5 host, or services used by that computer. Contact the relevant operator or provider about access, retention, and deletion of those records.

6. Children

Quenderin is not directed to children under 16 (or the applicable age in your country), and we do not knowingly collect personal data from them.

7. International transfers

Local inference does not transfer your content for processing. Website requests, model discovery, and downloads may be processed outside your country by the providers described above. Optional DeepSeek requests are sent to DeepSeek's infrastructure; Remote Harness sign-in and device records go to the server you configure, and session content goes to the selected computer and any services it uses.

Step 5 text goes to your selected host. These destinations may be in another country. Processing locations and safeguards depend on the provider or operator; local storage and session encryption do not guarantee a particular remote location.

8. Changes

We may update this policy; the "Last updated" date will change accordingly. Material changes will be reflected here.

9. Contact

Questions or requests: quenderin@aulenor.com.

Quenderin 0.6.0 — encryption technical annex

Prepared 28 October 2026 for owner/export-compliance review. This is a source-backed technical description, not a filed declaration, legal classification or exemption. It contains no owner identity, credentials or cryptographic key material.

Product, source and signed-artifact boundary

Quenderin is an iOS/macOS application for local-model work, with optional direct DeepSeek access and an optional “My computer” connection to a configured Host. This annex covers the Apple 0.6.0 source at 32bcb0cd3c26ad217abb339c389f9857596eaedb. Its remote-crypto sources, Swift package integration and app project settings are unchanged from Cloud 28 source 1761d8430ff51212c4bdca3a8bd45eb071471dca.

As recorded in RELEASE.md, Cloud 26 and 28 passed both signed archive actions and their SDK inclusion gates. Those gates check the SDK receipt, source provenance and real linked entry-point/proof definitions for iOS arm64 and macOS arm64/x86_64. This establishes inclusion in those signed exports; it does not establish a successful live Host handshake, encrypted remote session, model inference or completed store submission.

Final declarations must identify the actual build selected for distribution, not assume a later source is that build.

Cryptographic inventory

FunctionImplementation and purpose
Host secure sessionFixed Noise_IK_25519_ChaChaPoly_SHA256; X25519 identity/key agreement, ChaCha20-Poly1305 authenticated encryption, SHA-256 handshake hashing/key derivation. Identity private/public inputs are 32 bytes; transport authentication tags are 16 bytes.
Bundled libraryRust quenderin-remote-crypto 0.1.0; Snow pinned to 4bb43f50370bdb3e8b1b57814ac662864db2704f, with explicit default-resolver/curve25519/chacha20poly1305/sha2/getrandom features. Generated Swift bindings use UniFFI pin 7bc621ee9d0d15371d792612707ba5ed4111f950.
Algorithm providersThe selected Snow default resolver uses curve25519-dalek, RustCrypto chacha20poly1305 and sha2. These are bundled implementations, not CryptoKit calls. GuardedResolver delegates to them and rejects all-zero DH results. Extra lockfile dependencies do not establish selected algorithms.
OS facilitiesURLSession HTTPS/WSS for network transport; nonsynchronizing Apple Keychain credential/identity storage, using an iOS device-only accessibility class and the local macOS Keychain; Security SecRandomCopyBytes for the 32-byte enrollment seed; OS randomness through Snow/getrandom. CryptoKit SHA-256 also checks model integrity and computes public-identity fingerprints. No OS TLS cipher suite is asserted here.

The app introduces no new cipher, hash or key-agreement primitive. It adds the product-specific protocol context, enrollment checks, framing, counters and error policy around published implementations. That observation alone does not decide the legal classification of the complete protocol/product.

Actual data flow and invocation

The user configures a server origin and explicitly authorizes “My computer”. New device registration generates a local private seed and calls the Rust X25519 public-key derivation. The private seed is saved in Apple Keychain; the public identity is registered.

Account login and bearer-token exchange use HTTPS to the configured server; this account traffic is not described as Host end-to-end encrypted traffic.

After Host identity selection/verification, the production client creates a Noise IK initiator bound to the connection, Host and client device identifiers and the enrolled peer public key. The secure link encrypts fragmented business messages before relay transmission and authenticates/decrypts received messages before dispatch.

These messages support remote workspace/session operations and their results. The relay still processes control traffic and routing metadata. Local model chat does not invoke this Noise path. The Rust library supports both Noise roles; this native client selects the initiator role.

Source anchors: Cargo.toml, facade, resolver, Swift package, and the RemoteHarnessCryptoBackend, RemoteHarnessClientAccount, RemoteHarnessClientGateway, RemoteHarnessClientStorage and RemoteHarnessSecureLink files in QuenderinKit sources. The release profile requires the verified real SDK; a missing SDK cannot silently select the unavailable adapter.

Difference from Apple 0.5.0 (22)

Cloud 22's recorded source is 53994b799eb021bed10e2b58a727539283f02559. Its Apple sources use system HTTPS and CryptoKit SHA-256 integrity checks; neither the native Noise crate nor its Swift SDK target exists at that revision. Both targets declared ITSAppUsesNonExemptEncryption=false.

Noise was introduced in 7c3f7a45, native integration in 26df619d, and mandatory release packaging in 73920fd9, after the prior release. The 0.6 source removes the earlier assertion. Prior store approval and the old OS-only answer do not classify this new payload. The old signed binary has not been independently re-inspected for this annex.

Official review/filing route and unresolved owner inputs

Apple's current documentation table separates OS-only encryption from industry-standard algorithms implemented outside the OS. For the latter it specifies a French declaration when distributing in France. Its separate proprietary-algorithm row additionally specifies CCATS; this annex does not infer that row merely from Noise or application wrappers.

France is enabled according to the dated release record. No applicable exemption or existing filing reference has been established; open-source licensing alone is not proof of exemption. Use the exact artifact and territories in Apple's assessment/document-upload workflow.

ANSSI's current forms page directs applicants to Déclaration relative à un moyen de cryptologie — procedure 127585. The public page assigns the declaration to the supplier or first importer and lists company presentation, recent registration extract/foreign equivalent, commercial brochure and technical brochure, plus user/admin guides if available.

It offers FranceConnect or a demarche.numerique.gouv.fr account for sign-in and warns the form is still being developed. No account, draft or filing was created during this preparation.

Owner review must supply/confirm the declarant's legal capacity (individual or entity; supplier/first importer), legal identity/contact and any applicable registration evidence, intended distribution operations/territories, existing ANSSI receipt/exemption evidence if any, and the final release/build reference.

Those facts are unresolved and have not been inferred from private sources. The authenticated form's exact identity fields were not inspected. This annex can support the technical brochure; it does not replace the owner's other attachments, attestations or an ANSSI receipt. Complete that determination before setting an exemption flag or distributing the affected artifact.

Store Compliance Audit — Quenderin Native Apps

Date

2026-06-16 Scope: Quenderin native iOS (SwiftUI + QuenderinKit) and Android (Kotlin/Compose, ai.quenderin.app) store apps. Question: Can these native apps pass App Store + Google Play review? What the apps do: Offline, on-device LLM.

Onboarding → device-aware model picker → user-initiated download of ONE GGUF (0.4–9 GB) from HuggingFace → llama.cpp inference fully on-device → chat + a pure-logic agent loop (calculator / unit-convert / date math). No account, no backend, no analytics/telemetry. Only network call is the model download.

The "autonomous computer/device usage" (ADB device control) lives in the SEPARATE desktop Electron app. It is NOT in these store apps. The store apps have no AccessibilityService, no device automation, no screen capture of other apps. This audit is against the shipping store code only.

Prioritized Remediation Order

Phase 1 — Unblock submission (do these first; without them neither store accepts an upload):

  1. Host the privacy policy and fill the URL in App Store Connect + Play Console (+ in-app About/Privacy row). Unblocks both stores. Fast — the honest policy is short.
  2. Android <service> FGS-type fix — add the SystemForegroundService tools:node="merge" entry + xmlns:tools. Unblocks Android; prevents an API 34+ crash during the model download.
  3. Add PrivacyInfo.xcprivacy to the iOS app/QuenderinKit target with the two required-reason codes (E174.1, 3B52.1). Unblocks the iOS upload validator.

Phase 2 — Clear the major rejection risks before submitting:

  1. Add a Report/Flag affordance in chat + agent UIs (both platforms) — satisfies the Generative AI flag-mechanism requirement.
  2. File age rating at 17+ / Mature 17+ on both stores (questionnaire only, no code).
  3. Add an onboarding disclaimer + minimal output-side keyword filter for chat (covers ASRG 1.2 + Play AI-content "minimize risk").
  4. Fix STORE_SUBMISSION.md:49 and write store-specific copy / App Review notes that do NOT claim device control; scope ADB language to the desktop product.
  5. iOS EULA — opt into Apple's Standard EULA (one click).
  6. Decide on BackgroundModelDownloader — either wire UIBackgroundModes + the delegate hook, or mark it non-shipping.

Phase 3 — Cleanup / friction reduction (won't block, but file before first upload):

  1. ITSAppUsesNonExemptEncryption=false in Info.plist (kills the per-upload export prompt).
  2. Android backup rules — exclude models/; confirm conversation-history backup stance in the Data Safety form.
  3. Data Safety / store-description note — clarify the single HuggingFace GET carries no user data.
  4. App Review notes for iOS 4.2 — download size range, "be on Wi-Fi," onboarding is the first-use experience by design.

The app's architecture is genuinely review-friendly (offline, no data collection, minimal justified permissions, no device automation, targetSdk current).
