# Content report receiver

A small Google Apps Script V8 web app stores user-approved offensive AI content
reports for manual review by Quenderin's developer. The product must show the
editable excerpt, optional note, destination, and privacy explanation before an
explicit **Send report** action. This receiver does not collect a conversation,
device identifier, contact address, account, credentials, or model configuration.
Text may still contain personal information the user chooses to include. Google
hosts the endpoint and storage; its own request handling is separate from this
code, which makes no payload or exception log calls.

There are no dependencies to install. The custom code supplies the product's
strict schema, receipt reconciliation, and atomic capacity admission around
Google's existing Properties and Lock services. No mail, Drive files, Sheets,
external requests, advanced services, libraries, schedules, or triggers are used.
The manifest explicitly requests no OAuth scopes and disables exception logging.

## Request and receipt

POST `application/json` (optionally `; charset=utf-8`) to the deployment's `/exec`
URL. Only these keys are accepted; all except `note` are required:

| Key | Type and accepted value |
| --- | --- |
| `schema` | Number, exactly `1` |
| `reportId` | Lowercase UUID version 4, generated by the client |
| `platform` | String, exactly `android` |
| `appVersion` | 1–64 ASCII characters; starts with an alphanumeric character, then alphanumerics or `. + _ ( ) -` without spaces |
| `source` | `local-chat`, `agent`, `deepseek`, `remote`, or `step5` |
| `reason` | `harassment`, `hate`, `sexual`, `violence`, `dangerous`, or `other` |
| `content` | Nonblank user-edited excerpt, at most 6,000 UTF-8 bytes |
| `note` | Optional string, at most 1,000 UTF-8 bytes; absence becomes `""` |

Text is preserved exactly; lone UTF-16 surrogates are invalid. Unknown fields and
wrong types are rejected. The raw JSON body and the stored canonical JSON
envelope must each be at most **8,192 UTF-8 bytes**. The envelope includes receipt
metadata and JSON escaping; a request within the raw limit can still need a
shorter excerpt. Code-unit guards run before byte counting and JSON parsing.
Google receives the HTTP body before this application can check its size.

On verified persistence, including an identical retry:

```json
{
  "ok": true,
  "code": "received",
  "reportId": "12345678-1234-4234-8234-123456789abc",
  "receiptId": "87654321-4321-4321-8321-cba987654321",
  "receivedAt": "2026-10-28T00:00:00.000Z"
}
```

Failure responses contain only `{"ok":false,"code":"…"}`:

| Code | Meaning |
| --- | --- |
| `invalid_request` | Invalid JSON, media type, schema, field, or field byte limit |
| `too_large` | Raw request or stored envelope would exceed 8,192 bytes |
| `conflict` | The same report ID already has a different canonical payload |
| `unavailable` | Disabled, full, busy, quota/service failure, corrupt/unknown state, or unverified write |
| `method_not_allowed` | GET requests; no data or owner interface is exposed |

Parse `ok` and `code`: Apps Script's TextOutput API does not offer custom HTTP
status codes. Google redirects ContentService output to a one-time
`script.googleusercontent.com` URL; the native client must follow that HTTPS
redirect to read the JSON response, without reposting the report body there.
HTML, a login page, an unexpected redirect, a timeout, or malformed/missing JSON
does not establish delivery. Do not treat HTTP success alone as a receipt.

After an ambiguous attempt, preserve the **same ID and exact payload** for an
explicit manual retry. An identical payload returns its original receipt without
another write, even when the inbox is full. Changing any field after a send
attempt requires a new UUID; changed content under an existing UUID conflicts.
Missing and empty notes are equivalent, and JSON key order is irrelevant.
Do not retry in the background. `unavailable` can follow a successful write whose
readback failed; never claim that such an attempt definitely was not received.

## Storage and bounds

One Script Property named `report:<reportId>` holds one canonical JSON string:

```json
{
  "schema": 1,
  "receiptId": "87654321-4321-4321-8321-cba987654321",
  "receivedAt": "2026-10-28T00:00:00.000Z",
  "report": {
    "schema": 1,
    "reportId": "12345678-1234-4234-8234-123456789abc",
    "platform": "android",
    "appVersion": "0.4.1",
    "source": "local-chat",
    "reason": "other",
    "content": "Synthetic fixture excerpt.",
    "note": ""
  }
}
```

Maximum **32 reports**, each at most **8,192 bytes**, and at most **262,144 bytes**
of report values in total. The sole supported configuration property is
`qr.enabled`, exactly the string `true` or `false`. Absence means disabled;
unrecognized properties or invalid values fail closed. At most 33 properties are
used, within Google's documented 50-property manual management interface. A
dedicated standalone script must be used; do not mix this store with other code.

A Script Lock waits at most 200 ms. While held, one full store read validates all
records, capacity, and duplicates. A new report uses one property write and one
readback. There is no separate counter/index transaction. Existing reports are
never overwritten or deleted. Quota or readback failure returns `unavailable`
without attempting rollback or another write. Lock release runs in `finally`.
An owner changing the enable flag does not cancel an already admitted request.

The endpoint is anonymous and unauthenticated; reports are untrusted allegations,
not verified incidents or instructions. Anonymous spam can fill the bounded
inbox or exhaust shared Apps Script execution/property quotas. The fixed limits
protect storage and prevent automatic downstream work; they do not guarantee
availability, remaining account quota, or delivery during an outage. Review
cadence and capacity must be checked before this endpoint is offered to users.

## Deployment and manual review

1. Complete independent code review and run the fixture command below. Verify
   the intended existing consumer Google account and its current applicable
   terms, included use, quota sharing, and account restrictions. This source
   does not establish those account facts or authorize paid services. Keep the
   default Apps Script Google Cloud project; do not attach billing, provision a
   paid service, enable APIs, or add integrations for this inbox.
2. In that account, create a dedicated standalone Apps Script project. Paste only
   `Code.gs` and enable **Show appsscript.json manifest file in editor** in Project
   Settings, then paste `appsscript.json`. Save. Verify V8, empty scopes, no
   services/libraries/triggers, and no other code. Do not upload this README or
   the Node test file into the script project.
3. In **Project Settings → Script Properties**, add `qr.enabled` with the value
   `false`. Do not add credentials or other configuration. Keep editor access
   limited to the report reviewers; anyone with project editor access can read
   the report store.
4. Choose **Deploy → New deployment → Web app**; execute as the deploying owner
   and grant **Anyone** access, including people not signed in. The manifest
   equivalents are `USER_DEPLOYING` and `ANYONE_ANONYMOUS`. If anonymous access
   is unavailable or unexpected authorization scopes appear, stop and resolve
   that limitation. Use a versioned deployment's `/exec` URL, not `/dev`.
5. Record source revision/hash, deployment ID/version, owner account category,
   and dated account/quota/permission evidence in the existing release record.
   Verify public GET returns only `method_not_allowed` and a bounded synthetic
   POST while disabled returns `unavailable`, including JSON after the redirect.
6. When the reviewed source, owner access, policy/disclosure, Android client,
   and account limits are verified, deliberately set `qr.enabled` to `true`.
   Send one clearly labeled synthetic report, read its exact stored property in
   the owner UI, and verify an identical retry returns its original receipt.
   This uses one of the 32 slots; keep its fixture record identified in release
   evidence. Do not inject real offensive text or real user information as a test.
7. The owner reviews reports in **Project Settings → Script Properties**. Read
   each `report:<UUID>` value as JSON, including reason, excerpt, note, version,
   and timestamp; treat content as untrusted text. There is no public listing,
   search, download, admin, email, or notification endpoint. Never paste reports
   into public logs, issue trackers, or test artifacts. Follow the published
   privacy/retention process for actual reports.

To stop intake, set `qr.enabled` to `false`; keep all report properties intact.
To recover from full/corrupt storage, keep intake disabled, inspect the exact
state privately, and resolve through an explicitly authorized data-handling
process. Do not delete reports, reset IDs, raise limits, or replace the project
as an automatic recovery step. There is no automatic purge. Updating/rolling
back a deployment must preserve this existing script's report properties and
the schema-1 reconciliation behavior.

## Verification

Run from the repository root with Node 20+:

```sh
node --test services/content-report-receiver/receiver.test.mjs
```

Fixtures use a fake Script Lock, properties, clock, receipts, ContentService, and
logging traps. They cover normal persistence/readback, canonical retries and
conflicts, capacity and overlap, disabled/unknown/corrupt state, byte boundaries
and escaping, invalid Unicode/types, quota/lock/write/readback failures,
ambiguous-write reconciliation, GET privacy, and the no-scope/no-log/no-network
configuration. They install nothing and make no live requests. Hosted deployment,
actual account/terms, owner UI readback, redirects, and native-client behavior
remain separate release checks.

Official documentation verified 2026-10-28:

- [Properties Service](https://developers.google.com/apps-script/guides/properties): script-wide string storage and manual management up to 50 properties.
- [Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas): consumer property read/write quota 50,000/day, value limit 9 KB, total store 500 KB; execution limits and quotas are shared and may change, and quota exhaustion stops execution.
- [Lock](https://developers.google.com/apps-script/reference/lock/lock): bounded `tryLock` and explicit release.
- [Content Service](https://developers.google.com/apps-script/guides/content) and [TextOutput](https://developers.google.com/apps-script/reference/content/text-output): JSON output, redirect behavior, and output API.
- [Manifest](https://developers.google.com/apps-script/manifest) and [web app configuration](https://developers.google.com/apps-script/manifest/web-app-api-executable): V8, exception logging, explicit scopes, deployment identity, and anonymous access.

These are provider documentation checks, not evidence of the current owner's
remaining quota or a completed deployment.
